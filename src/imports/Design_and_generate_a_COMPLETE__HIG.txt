3. DYNAMIC PERMISSION MODEL
============================================================

Implement the concept of dynamic permission throughout the UI.

Permission depends on:

- role
- assigned capability
- organization
- branch
- team
- data scope
- action permission

Examples:

Employee:
Can view own personal HR data.

Team Lead:
Can view assigned team data.

HR Branch:
Can manage employees within assigned branch.

HR Head:
Can access company-wide HR data according to granted permissions.

System Admin:
Can manage system configuration and accounts, but does NOT automatically gain access to sensitive HR business data.

Action-level permission:

VIEW
CREATE
EDIT
DELETE
APPROVE
REJECT
EXPORT
PUBLISH
LOCK ACCOUNT
VIEW SENSITIVE DATA

A user can have:

VIEW but not EDIT.

VIEW but not EXPORT.

APPROVE but not DELETE.

This must be visually represented through:
- hidden actions
- disabled actions
- read-only states
- contextual menus
- permission-aware buttons
