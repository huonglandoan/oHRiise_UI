============================================================
PART L — DO NOT FAKE COMPLETENESS
============================================================

Do NOT solve missing functionality by adding:

- a random card
- a KPI
- a generic table
- a decorative empty page
- a "Coming soon" state
- a single modal pretending to be a module

Each missing domain needs an actual usable flow.

However, do NOT overbuild functionality that is not
supported by the current functional requirements.

The goal is:

FUNCTIONALLY REPRESENTATIVE
+
VISUALLY COHERENT
+
INTERACTIVE DEMO

not an entire production HR platform.

FINAL INSTRUCTION
============================================================

DO NOT regenerate the whole oHRiise application.

PATCH THE EXISTING APPLICATION.

Prioritize correctness and completeness over creating
more decorative UI.

If an existing screen is already good:
KEEP IT.

If a screen is missing:
ADD IT.

If a screen currently uses a generic template despite
representing a different business domain:
REFACTOR THAT SCREEN into a domain-specific layout.

If a flow is disconnected:
CONNECT IT.

If a button is decorative:
MAKE IT INTERACTIVE.

The final prototype should feel like ONE coherent
oHRiise HR operating system whose UI visibly reflects
the Use Case architecture and functional workflows.
